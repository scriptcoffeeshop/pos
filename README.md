# Script Coffee POS

Script Coffee POS 是門市平板點餐、線上訂單中樞與 GODEX DT2X 區域網路列印的初始專案。第一版已建立 Vue 3 + Vite + TypeScript 前端工作台，並接上獨立 Supabase `pos-api` 作為商品、訂單與列印工作的後端入口；後續再接 LINE Login、LINE Pay / 街口支付與 Capacitor Android APK。

## 初版範圍

- 消費者線上訂位頁：`?view=reservation` 會進入 Script Coffee 專屬訂位入口，並讀取 `engagement_settings.reservationWebsite` runtime 設定。後台「iCHEF 補齊」可開關線上訂位、設定餐廳名稱/電話/地址/公告、人數上下限、訂位間隔、用餐時間、最早提前分鐘數、開放天數、每週可預約時段，以及 iCHEF 式「特殊訂位日」：特定日期或日期區間可整日不開放訂位，也可自訂時段取代原本固定時段，包含跨夜時段。設定會由 `/settings/runtime` 同步到消費者頁與新平板。公開 `POST /reservations` 會套用同一套規則後寫入 Supabase `reservations`，黑名單手機會被公開 API 阻擋，門市手動新增訂位則維持黑名單提示與二次覆蓋。
- 訂位桌位容量控管：依 iCHEF「可線上訂位桌位」「桌位使用時間」「座位保留時間」邏輯補上容量檢查。`20260510170000_add_reservation_table_assignment.sql` 新增 `reservations.assigned_table_ids`，公開訂位成功時會從 `floor_plan` 桌位容量與 `reservationWebsite.onlineTableIds` 中分配桌號；同時段已預訂、已發送提醒、已保留訂位與已帶位桌位會被占用，舊有未分配桌號的訂位會用人數保守占用容量。後台可選哪些桌開放線上訂位、設定是否允許併桌、用餐時間與座位保留分鐘數，換平板、重開 App 或 fresh reinstall 後仍以資料庫 assigned table 為準。
- POS 訂位管理：依 iCHEF POS「訂位管理」「POS 訂位提醒標示」「特殊時間設定」「消費者通知與訂位狀態」「訂位報到帶位開單」「修改訂位資訊」補上平板工作區。工具箱可進入「訂位管理」，以日/週/月檢視、狀態篩選、同區間摘要查看訂位；狀態涵蓋 `booked` 已預訂、`reminded` 已發送提醒、`confirmed` 已保留訂位、`seated` 已帶位、`cancelled` 已取消與 `no_show` 未出席，列表會標示遲到、座位數不足、桌位重疊、未排桌與特殊訂位日/不開放訂位標籤。POS 可直接新增訂位並指定一張或多張 `floor_plan` 桌位；既有訂位可修改日期時間、人數、桌位、狀態、訂位人資訊、標籤與店內備註，並提供前/後一個訂位時段快速調整。到訂位時間前 2 小時起可按「帶位開單」，系統會建立內用草稿單並帶入姓名、電話、訂位人數、客人/店內備註、標籤與保留桌位，再把訂位狀態改為 `seated`。當 POS/後台同步訂位或公開訂位分配桌位時，`pos-api` 會依台北時間把隔兩天凌晨 1 點已過且仍未帶位/取消的訂位自動改為 `no_show`。桌位地圖會顯示下一組已安排訂位時間，所有訂位資料仍以 Supabase `reservations` 為來源，不依賴 localStorage。
- POS 候位提前點餐：依 iCHEF「現場候位登記與提前點餐」流程，候位列可直接按「提前點餐」建立內用草稿單並帶入姓名、電話、人數與備註；候位清單會把草稿 `orderId` 存在 `floor_plan.waitline`，點「開啟點餐」可續編同一張單。空桌入座時會把同一張草稿單改寫為該桌內用單、更新樓層/桌位/人數備註並載入點餐頁，讓候位等候期間先點的品項在換平板、重開 App 或 fresh reinstall 後仍可追溯。
- 門市 POS 第一屏：工作站進入後預設顯示接近 iCHEF Server 的「桌位地圖」，內用與外帶/外送分成第一層切換；桌位地圖支援多樓層切換，每個樓層可有不同桌數、桌號、位置與大小，內建 A1/A2/A3 桌卡、空桌/進行中/可交付/鎖定狀態、人數、金額、未出單等待與滯留時間，選桌後可開桌點餐、開啟訂單、移桌或清桌，候位區可填寫姓名/電話/人數/備註後安排到空桌。連點工具箱 6 下進入後台編輯模式後，可新增/刪除樓層、新增/刪除桌位、修改桌號/容量、拖曳桌位位置並調整桌子大小。樓層、當前樓層、桌位配置、桌位容量、桌位顯示設定、各桌人數與候位清單會寫入 `floor_plan` runtime setting，Realtime 或 fallback `/settings/runtime` 會把資料同步到新平板；localStorage 只保留 API 失敗時的暫存快取。內用訂單會以「樓層 1F、桌位 A1」這類備註標記對應桌卡，移桌會走 `/orders/:id/floor` 更新訂單備註與顧客名稱並記錄稽核；若訂單不能直接回購物車編輯，按「開啟訂單」會切到訂單中心並展開該筆訂單供檢視。外帶 / 外送頁保留搜尋、今日/今日之後/較舊、取餐方式、來源與取餐/送達時間正反序排序。固定右側導航列已移除，工具箱改為可自由拖曳的浮動入口，主畫面上方可直接按「新增候位」或在外帶/外送頁按「新增外帶」進入點餐；點餐頁改為接近 iCHEF 出單畫面的「左側票券、右側分類列與商品大方塊」雙區塊。新增外帶會立即建立可見佇列訂單並依序給 `001`、`002`，即使尚未加入品項，回到外帶/外送頁仍保留該單；點佇列上的櫃台訂單可回購物車繼續編輯品項，櫃台自己建立的外帶/外送單不再顯示鎖定逾時。購物車左欄改為高密度票券清單，服務方式直接切換，付款與「需要袋子」等常用備註同列顯示，常用備註可再次點按取消且會用主色與勾選圖示顯示已選狀態；多個品項註記會用可換行 chip 呈現，不再截斷後段文字；品項列壓縮為商品/註記、數量、出單狀態、金額四欄，可對單一明細切換「暫停出單」且不影響結帳；底部提供高對比且不重疊的「結帳」「出單」「結帳不出單」三個操作，同一張單會沿用原單號。顧客、服務方式、付款與常用備註可在票券上直接修改，內用單完成後回桌位地圖，外帶/外送單完成後回訂單中心；POS 啟動後會記住鍵盤出現前的最大工作台高度，Android 鍵盤開啟時不再將左側票券往上推擠。飲品品項會先開啟選項面板，必選「飲品溫度」未完成時會在面板與票券行項提示；商品方格與 Cart 品項都可直接輸入數量，也保留正負號調整；POS 供應狀態為停售、售完或暫停供應的商品會保留在菜單中反灰且不可點，並標示「停售」或售完狀態。商品分類列支援左右滑動快速切換「全部 / 咖啡 / 茶飲 / 輕食 / 零售」等頁面；連點工具箱 6 下進入後台編輯模式後，分類 tab 與商品卡片可長按拖曳交換順序，拖曳與位移手勢會短暫抑制點擊，避免平板誤觸成點餐，排序寫回後也會重新同步後端資料。POS 已加入快速加購跨重啟保留、常用備註 chip、未送出櫃台訂單自動恢復、佇列篩選/搜尋與整合式重設跨重啟保留、現代票券式訂單列、訂單明細展開、訂單左滑露出已完成/已取餐與刪除，櫃台佇列刪除不需額外驗證，外送/線上訂單按「已取餐」會從目前佇列歸納為已完成；外帶/外送頁也補上 iCHEF 式「快速出店」，可依來源與完成時間批次把已付款且到點、未被其他平板鎖定的外帶/外送單寫成 `served`，重開 App 或換平板都不會再回到待處理佇列；列印單左滑刪除、庫存/低庫存提示、下單原子扣庫存、防搶單平板鎖定、收款確認、未收款訂單作廢、已收款退款沖銷、列印重印紀錄、正式開班/關班、現金臨時收支、單屏式關帳摘要/交班預檢/班別對帳、關帳異常檢查與強制確認、鍵盤捷徑（`/` 搜尋、`1`-`6` 加購、`Cmd/Ctrl+Enter` 出單）。
- 影片參考導入：在不改預設色系的前提下，補上 iCHEF 式可拖曳工具箱、外觀設定卡片、桌況頁進階條件（日期、取餐方式、來源、排序）與常駐供應狀態入口；工具箱會浮在整個應用所有主要頁面上方，供應狀態全螢幕頁也可直接開啟，長按工具箱 2 秒可退出後台編輯模式。外觀設定點入後可切換深色模式，並用 -200% 到 +200% 滑桿調整整體介面縮放、畫面密度與文字大小，也可調整工具箱浮動按鈕透明度；設定會寫入 `pos_appearance` runtime setting，POS 啟動、Realtime 事件或 fallback `/settings/runtime` 同步時自動套用到新平板。POS 介面以固定平板 viewport 舞台縮放以避免水平溢出。供應狀態支援搜尋、分類、狀態篩選、批次暫停/恢復、儲存確認與回復上一個動作，並可在工具箱直接新增/刪除分類、商品、註記大項、註記選項與商品註記綁定；註記群組建立後仍可切換必選/非必選，儲存時會把分類順序、註記群組、商品綁定與註記停售狀態同步到 `online_ordering` runtime，商品供應狀態本身則以 `products.is_available` 與 POS/線上/掃碼可見欄位為準，成功寫入資料庫才視為已儲存；POS 商品同步會保留 `pos_visible` 的停售商品以便反灰顯示與後續恢復，線上/QR 查詢仍只回傳可售品項，讓線上點餐頁與新平板透過 Realtime 或 fallback 短輪詢取得同一套資料。後台營運紀錄會整合平板心跳、開關班與關鍵操作時間線，線上點餐設定可控制接單、預約、平均備餐時間、未確認提醒、接單確認、提示音模式與音量。主佇列第一層已收斂為搜尋、條件與訂單列，訂單列使用短單號、鎖定標籤不外露平板識別，並維持深色模式可讀性；履約預警、任務快篩、SOP 與交班預檢資料模型仍保留，後續適合陸續放入工具箱延伸。
- 消費者線上點餐頁：依後台「線上」通路與 `online_ordering` runtime 設定顯示菜單，支援購物車、取餐/內用/外送、希望時間、外送地址、顧客資料與線上建單；後台可設定 iCHEF 式結帳說明，並分別開關統一編號與載具條碼欄位，送單後會寫入 Supabase `orders.tax_id`、`orders.invoice_carrier_barcode`，POS 訂單明細、線上新單提醒與顧客聯/收據列印都會顯示同一份資料。後台也可分別開關自取、內用掃碼與外送送單狀態；消費者頁會停用被關閉的服務方式，`pos-api` 會拒絕繞過前端送出的 disabled service mode。線上預約訂單設定支援取餐時間間隔、最長可預約天數與多段星期/時間窗；消費者頁的希望時間會依平均備餐、外送車程、預約天數與時段限制，API 也會重新驗證。線上支付模組支援取餐時付款、LINE Pay、街口、線上刷卡與轉帳的啟用、顯示名稱、排序與 iCHEF 式「結帳開錢櫃」開關；排序會影響消費者頁付款方式顯示，已停用付款方式會由前端隱藏且由 API 再次拒絕。外送規則存在同一份 `online_ordering` runtime，後台可設定外送費、外送最低金額、滿額免運與預計車程；消費者頁外送時只顯示 LINE Pay、街口與線上刷卡等線上付款方式，總額會加入外送費，API 會依扣除折抵後金額重新計算並拒絕未達門檻或非線上付款。商品會依平板端綁定的註記大項開啟選項面板，必填/最多選幾個與加價會進購物車，註記停售會即時隱藏；分類顯示順序跟隨 `online_ordering.menuCategories`，商品顯示順序跟隨 `products.sort_order`，runtime 與商品異動會先由 Supabase Realtime 事件觸發重新載入，並保留每 15 秒 fallback 同步。暫停接單時保留菜單瀏覽但阻擋加入與送出。
- 套餐商品：依 iCHEF 商品管理的單點/套餐模型，後台供應狀態可在商品底下建立「套餐子項目」，設定必選/選填、最少/最多份數、是否允許重複選擇、可選單點商品與加價。設定保存於 `online_ordering.comboProductAssignments`，`20260512070000_add_combo_product_runtime_settings.sql` 也讓正式訂單把選到的子商品保存到 `order_items.combo_items`。POS 與消費者線上點餐會開同一個套餐選擇面板，價格、票券註記、訂單明細、重開 App、換平板與 fresh reinstall 都從 Supabase runtime/API 還原；若套餐內被選到的單點商品本身有註記群組，也會在同一面板內要求/保存子商品註記與加價。列印規則可用套餐內被選到的商品判斷列印站，正式建單時也會依套餐子商品扣可售庫存、套用子商品耗料規則，並由 `20260512083000_add_combo_child_option_consumption.sql` 讓套餐子商品註記也觸發 option 類自動耗料。
- 商品文字註記與臨時加減價：對照 iCHEF「商品加減價與註記」，POS 商品選項面板新增文字註記、`+ 加價` 與 `- 減價` 欄位；一般商品加入票券後也可點品項名稱回到同一面板補註記。文字註記會保存為品項 `options`，加減價會反映在明細 `unit_price`，正式建單、草稿 finalize、列印與訂單中心都沿用既有 Supabase 訂單欄位，不新增 localStorage 來源；若後台保護「變價註記」操作，手動加減價會先要求員工識別碼。

- 混合支付與交易明細：依 iCHEF 官方知識庫「同張訂單使用多種支付模組」與「列印多張交易明細」補上付款頁混合支付。`20260511213000_add_order_mixed_payments.sql` 新增 `orders.payment_breakdown` 與 `orders.transaction_receipt_count`，同張單可分配多筆付款金額、逐筆標記已結/未結、限制同張單線上支付模組只能使用一種；關帳付款方式會依各筆金額分攤，不再只看訂單主付款方式。結帳時可設定自動列印交易明細張數，訂單中心也可事後補印「交易明細」；收據/交易明細 payload 會列出混合支付明細。
- 區網列印 POC：出單機 IP、服務方式、印單時機、商品分類、指定品項、貼紙/收據與份數可由後台設定；前台列印站已改成 iCHEF 式「出單機設定 / 印單規則 / 列印佇列」三段，不再混入庫存、商品供應管理或額外列印流程說明。印單規則可分別勾選「出單」與「重印」，`printer_settings.rules[].timings` 會決定初次出單或訂單列重印時是否套用該規則，舊 runtime 由 `20260512101000_add_print_rule_timings.sql` 自動補成兩者啟用。印單規則的分類名稱點擊只切換右側品項列表，分類 checkbox 才會整類勾選；整類勾選時右側品項全顯示為已勾，取消單一品項會把規則轉成同分類其他品項的個別勾選並取消分類勾勾，外帶、內用、外送規則共用這套邏輯。依 iCHEF 已裁貼紙規則補上「不計算商品」獨立選取，`countExcludedCategories` / `countExcludedItemIds` 只影響貼紙上的總商品序號，不會把品項從列印範圍移除；例如袋子可列印但不納入 `1/3` 這類總數。只有被納入規則且未在購物車明細按「暫停出單」的品項才會產生 payload；暫停出單會保存到草稿 `draft_lines.printPaused` 與正式 `order_items.print_paused`，所以換平板、重開 App 或重印都不會把該明細補印，但金額與結帳仍保留。內用與外送預設單據改為「內用貼紙」「外送貼紙」。訂單列與 Next 訂單區可手動列印 iCHEF 式「訂單 QR Code」與「顧客聯」：QR label 使用 GoDEX EZPL QR command 指向 `order.scriptcoffee.com.tw?source=qr`，含訂單與桌號參數；顧客聯會建立獨立 `print_jobs` 並可走 Android LAN printer。列印站可送出 EZPL healthcheck label，訂單會依 runtime 規則拆分 EZPL payload 與 `print_jobs`，列印站會顯示列印單清單並支援滑動刪除，Android APK 內的 `LanPrinter` plugin 會逐筆用 TCP socket 送到 GODEX DT2X，瀏覽器版只做預覽與 print job。
- Supabase 後端：獨立專案已綁定，包含 POS schema migration、金流 webhook 冪等事件、`pos-api` Edge Function 與 `pos_realtime_events` Realtime invalidation 表；交易型 `SECURITY DEFINER` RPC 只授權 `service_role`，外部請求固定經過 `pos-api`。
- 操作稽核：建單、收款、退款、付款逾期、作廢、訂單狀態、平板鎖定、商品/設定異動、會員建立、會員券建立/退回、錢包調整、開關班、現金臨時收支、錢櫃開啟與員工打卡會寫入 `pos_audit_events`，商品稽核會標出庫存/售價等欄位的異動前後與差額，後台可直接讀取最近紀錄追查。
- 工程規範：TypeScript strict、ESLint、禁止 legacy DOM/event bridge 的 guardrails。
- GitHub Actions：guardrails、typecheck、lint、Edge Function check、build，並在 `main` 自動部署 GitHub Pages 與 Supabase。

GitHub 倉庫：<https://github.com/scriptcoffeeshop/pos>，目前為 public。

## 主要決策

- 前端全面 Vue-owned state，不新增 inline `onclick/onchange`、`data-action` 事件代理、`window.*` 全域 API 或 `innerHTML` 資料渲染。
- 先用 GitHub Pages 承載消費者線上點餐與 Web POS；硬體列印走 Capacitor Android APK 內的 `LanPrinter` TCP socket plugin，直接送 EZPL 到 GODEX DT2X。
- 後端沿用咖啡訂購專案經驗：Supabase PostgreSQL + Deno/Hono Edge Functions，金鑰放 GitHub Secrets 或 Supabase，不進 git。
