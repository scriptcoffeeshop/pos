# Script Coffee POS

Script Coffee POS 是門市平板點餐、線上訂單中樞與 GODEX DT2X 區域網路列印的初始專案。第一版已建立 Vue 3 + Vite + TypeScript 前端工作台，並接上獨立 Supabase `pos-api` 作為商品、訂單與列印工作的後端入口；後續再接 LINE Login、LINE Pay / 街口支付與 Capacitor Android APK。

## 初版範圍

- App 主機 / 子機模式：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「iCHEF POS App 運作模式」知識庫，確認同一 Store ID 僅一台 iPad 可作主機，子機需與主機同網路與同 App 版本，且子機不可執行「套用新設定檔登入」。Script Coffee POS 新增 `engagement_settings.appOperation`，後台「iCHEF 補齊」可設定主機 station id、子機清單與子機上限；前台會顯示目前是主機或子機，子機會停用「套用新設定檔」，並把工具箱限縮到交易查詢與作廢、錢櫃管理、裝置管理、小結與系統資訊。未指定主機時維持單機主機相容模式，不新增 migration。
- 外帶預約訂單：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「新增外帶預約訂單」知識庫，確認流程為外帶/外送區新增現場外帶單、點日曆調整取餐時間，最後可「儲存後返回」暫不印單或直接「出單」。Script Coffee POS 點餐票券的日曆面板現在可直接編輯顧客、電話與取餐/送達時間，並提供預設取餐時間、前後時段與清除快捷；票券底部新增「儲存後返回」會把含品項與 `requested_fulfillment_at` 的櫃台單同步回外帶/外送佇列但不建立列印意圖，之後仍可依取餐時間排序、提醒或再開單出單。
- 商品大數量銷售：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「商品大數量銷售的調整方式」知識庫，確認單品可在點餐頁鍵盤輸入數量，套餐則先完成套餐子項目與註記後再輸入數量。Script Coffee POS 商品方塊與票券品項的數量輸入現在共用商品庫存上限，會把同一商品的標準品項與不同註記/套餐變體一起計算，避免直接輸入或按加號超過 `products.inventory_count`；點餐票券與商品方塊的數量控制也調整為平板可點的 44px 觸控尺寸。
- 商品條碼點餐：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「商品條碼點餐」知識庫，確認條碼需在後台商品管理手動設定、不可重複、上限 48 字元，支援半形英數字與 `-.$/+%:`，POS 點餐頁可用 iPad 相機或掃碼器掃描。Script Coffee POS 新增 `products.barcode`、格式檢查與非空唯一索引；後台「商品菜單」可設定與搜尋條碼，POS 點餐頁右上角新增條碼掃描入口，支援相機辨識的環境會開啟預覽，不支援時可直接用掃碼器輸入 Enter。掃到可售商品會直接加入票券；有必選註記或套餐時會開啟選項面板，停售、售完或暫停供應商品不會被條碼加入。
- 移桌與併單：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「將訂單移桌或併單」知識庫，確認候位區與內用區訂單可拖移到空桌，也可拖移到另一張訂單合併，併單後來客數加總，且列印規則可勾選「移桌」「併單」時機自動出單。Script Coffee POS 桌位地圖右側在選取進行中桌位後提供「移桌」空桌快捷與「併單」目標桌快捷；`pos-api` 新增 `POST /orders/:id/merge`，可合併草稿品項或已出單明細、加總金額/服務費/折扣/點數/標籤與來客數，來源單改為作廢並寫入 `order.merge` 稽核。`printer_settings.rules[].timings` 也支援 `move` 與 `merge`，預設仍只啟用初次出單與重印，店家可自行勾選移桌單或併單單。
- 批次點餐清單操作：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「批次進行點餐清單中的商品操作」知識庫，確認店家可依同一狀態的品項批次重印至廚房或刪除。Script Coffee POS 點餐票券新增「批次商品操作」列，可選「出單」或「暫停」狀態，即時計算符合明細與件數；「重印」會先儲存目前票券，再只針對符合狀態的明細建立重印列印工作，「刪除」會沿用後台刪品項操作驗證並批次移除符合狀態的明細。
- 出餐管理與品項完成：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「出餐管理」知識庫，確認 iCHEF 可用顧客聯手寫註記，也可在 POS 開啟「出餐確認」後逐品項標記出餐完成，未全數出餐時訂單顯示待處理，全部完成後顯示完成。Script Coffee POS 在 `order_items` 新增 `fulfilled_at` 與 `fulfilled_by_station_id`；訂單中心展開「明細」後可逐品項按「待出餐 / 已出餐」，狀態經 `pos-api` 寫回 Supabase 並記錄 `order.item.fulfillment` 稽核。所有正式明細都已出餐時，訂單會自動推進為「可交付」；若取消其中一項，訂單會回到製作中。出餐確認關閉時仍維持首次出單自動可交付的既有流程。
- 請款明細與顧客聯差異：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「提供請款明細供消費者確認結帳內容」知識庫，確認顧客聯不含折扣總計、請款明細需包含服務費/其他費用、優惠折扣與點數折抵，總計顯示折扣後金額。Script Coffee POS 的付款頁現在可在結帳前直接列印「請款明細」；訂單中心未收款單顯示「請款明細」、已收款單顯示「交易明細」。`buildBillingStatementPayload()` 與 `buildTransactionDetailPayload()` 會列出 `ITEMS / SERVICE / EXTRA / DISCOUNT / POINTS / COUPON / TOTAL`，顧客聯則保留折扣前總額，讓兩種單據用途分開。
- 重印顧客聯整理加點單據：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「同單多張顧客聯合併列印」知識庫，確認 iCHEF 每次出單的顧客聯只會顯示當次出單商品與小計，多次加點後建議在點餐頁按「重印顧客聯」整理成同單完整顧客聯。Script Coffee POS 在已建立或載回購物車的票券底部新增顧客聯圖示按鈕；按下後會先保存目前票券，再用同一訂單完整明細建立「顧客聯」print job，沿用既有 Android LAN printer 與列印紀錄流程。
- 出單機與印單規則排序：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「調整排序讓出單順序符合店內營運流程」知識庫，確認 iCHEF 出單會先依出單機排序，再依同一出單機內的印單規則排序列印，且印單規則只能在同一出單機內調整位置。Script Coffee POS 的前台「列印」工作區與後台「出單規則」都補上出單機/印單規則上下排序按鈕；`buildOrderPrintPlan()` 現在以 `printer_settings.stations` 順序為外層、各站 `printer_settings.rules` 順序為內層建立 print jobs，未啟用或未自動列印的出單機會略過。
- App 套用新設定檔：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「App 套用新設定檔」知識庫，確認後台可先調整設定，POS 端只有選擇「套用新設定檔登入」時才更新。Script Coffee POS 會為每台平板保存已套用的 runtime 設定檔快照；偵測到後台 `runtime_settings` 有新版本時，訂單、班別與心跳仍照常同步，但商品/線上/列印/桌況/權限等 runtime 設定會先標示「新設定檔」並保留目前套用版本，操作員可在 topbar 或工具箱按「套用新設定檔」後一次套用最新設定。
- 線上點餐工具箱設定：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「線上點餐功能設定」知識庫，確認 iCHEF POS App 位置為「工具箱 > 線上點餐功能設定」，且「營運方式與流程」全店同步、「訂單通知」每台 iPad 分開設定。Script Coffee POS 的工具箱「線上點餐」現在會開啟 POS 端設定面板；可直接切換線上送單 / 僅菜單瀏覽、自取 / 內用掃碼 / 外送開放狀態與線上新單是否需平板接單，並在同一面板調整目前平板的接收通知、提示音、服務方式、提示聲模式、音量與內用桌位通知範圍。全店狀態寫入 `online_ordering.enabled`、`serviceModeAvailability` 與 `acceptanceRequired`，每台平板通知寫入 `online_ordering.notificationRouting`，不新增 migration。
- 線上新單通知：對照 iCHEF POS「線上點餐功能設定」的每台 iPad 訂單通知，POS 桌位地圖右側與工具箱「線上點餐功能設定」都可調整通知。每台平板可獨立開關接收通知、提示音、服務方式與內用桌位範圍；未指定桌位時接收所有內用桌位。設定保存於 `online_ordering.notificationRouting`，前景提醒、Web 背景通知與 Android `OnlineOrderNotifier` / `OnlineOrderPollingService` 都會套用同一份 runtime，舊 runtime 由 `20260512163000_add_online_notification_routing_settings.sql` 補上預設空設定。
- 線上僅菜單瀏覽模式：2026-05-12 以 Safari / Computer Use 觀察 iCHEF 後台「內用掃碼點餐」功能狀態，確認可切換為「無點餐功能，僅菜單瀏覽」。Script Coffee POS 以既有 `online_ordering.enabled=false` 對應此狀態，不新增 migration；後台線上點餐設定改以「功能狀態 / 僅菜單瀏覽」呈現，消費者線上/掃碼頁仍載入菜單與店家資訊，但送出按鈕會顯示「僅菜單瀏覽」且前端與 `pos-api` 都阻擋送單。
- 線上接單與接受但不出單：2026-05-12 以 Safari / Computer Use 進入 iCHEF 網頁版後台「雲端餐廳 > 內用掃碼點餐」，確認接單選項可讓接單畫面選擇「接受但不出單」。本專案沿用既有 `online_ordering.acceptWithoutPrinting` runtime 欄位；後台勾選「接單時可接受但不出單」後，線上/掃碼待接單清單、訂單內容彈窗與浮動提醒會同時提供「接單並出單」與「接受不出單」。接單並出單會先鎖定訂單再執行 `printOrder(order.id, 'order')`，接受不出單只會鎖定並寫入 shared reminder state，不新增資料庫 migration。
- 線上付款拒絕接單退款：2026-05-12 以 Safari / Computer Use 檢查 iCHEF 後台「內用掃碼點餐 > 支付模組設定」，確認線上付款訂單被拒絕或取消時系統會自動退款。POS 待接單提醒現在會依付款狀態分流：`pending` 線上/QR 訂單按「拒絕接單」仍呼叫作廢流程並標成付款失敗；`authorized` 或 `paid` 訂單會呼叫既有 `refundOrder` / `/orders/:id/refund`，讓訂單狀態改為作廢、付款狀態改為已退款、寫入退款流水，並沿用會員券、點數與電子發票回補規則。拒絕後仍會寫入 shared reminder state，換平板或 fresh reinstall 後不會重複提醒。
- 優惠/點數現場付款限制：同一個 iCHEF 支付模組頁也確認優惠活動、點數活動須請消費者選擇「現場付款」，再於 POS 結帳時操作。消費者線上/QR 頁套用自動優惠後會只保留「取餐時付款」；若目前服務方式必須線上付款，例如外送或內用掃碼先結，前端會阻擋送單並提示需調整服務方式或活動適用範圍。`pos-api` 也會重新檢查自動優惠、點數折抵與優惠券碼，非現場付款會回 409，避免舊頁或 API 繞過前端。
- 基本支付自定義記錄：2026-05-12 以 Safari / Computer Use 參照 iCHEF 官方「多元支付整合：同台 POS 搞定」，確認基本支付記錄包含現金、信用卡與可用於禮券/兌換券的自定義支付。Script Coffee POS 新增 `PaymentMethod='custom'` 與 `20260512260000_add_custom_payment_method.sql`；付款頁、票券付款快捷、拆單、混合支付、列印 payload、營運日報與 `pos-api` 建單/草稿 finalize 都可保存自定義支付。自定義支付屬於現場基本支付，不加入線上點餐支付模組與外送/QR 先結線上支付白名單。
- 點餐頁註記欄位數量：2026-05-12 以 Safari / Computer Use 觀察 iCHEF 後台「店面流程與警示 > 點餐頁顯示設定」，確認「註記欄位數量」可選每列 1、2、3 欄。Script Coffee POS 新增 `engagement_settings.orderPageDisplay.noteColumns`，後台「iCHEF 補齊」可同樣選擇每列 1/2/3 欄，點餐頁商品註記與套餐子商品註記格線會即時套用；舊 runtime 由 `20260512234500_add_order_page_display_runtime_settings.sql` 補成預設每列 3 欄。
- 店面流程自動出店：2026-05-12 以 Safari / Computer Use 觀察 iCHEF 後台「店面流程與警示」，確認內用自動出店預設關閉、外帶自動出店預設開啟，且內用掃碼已結帳訂單仍需手動出店。Script Coffee POS 新增 `engagement_settings.workflowAlerts.dineInAutoExitEnabled` 與 `takeoutAutoExitEnabled`，後台「iCHEF 補齊」可分別控制內用與外帶/外送；訂單完成製作且付款狀態為 `paid` 或 `authorized` 時會自動寫成 `served`，內用掃碼單保留手動出店。舊 runtime 由 `20260512240000_add_auto_exit_runtime_settings.sql` 補上內用關閉、外帶/外送開啟的預設。
- 店面流程出餐確認：同一個 iCHEF 後台頁面顯示「出餐確認」預設關閉；關閉時出單後品項自動變更為已出餐，開啟時需手動確認。Script Coffee POS 新增 `engagement_settings.workflowAlerts.fulfillmentConfirmationEnabled`，後台「iCHEF 補齊」可切換；出餐確認關閉且首次出單建立列印工作或列印成功時，訂單會自動從 `new/preparing` 推到 `ready`，再接續套用自動出店。舊 runtime 由 `20260512241000_add_fulfillment_confirmation_runtime_setting.sql` 補成預設關閉。
- 店面流程警示門檻：同一個 iCHEF 後台頁面也有候位等待、內用未出單、內用出餐等待、店內滯留、外帶未出單、外帶出餐等待、外帶等待與預約取餐提前提醒等警示開關。Script Coffee POS 新增對應 `workflowAlerts.*WarningEnabled/*WarningMinutes` 與 `scheduledPickupReminderEnabled`；後台「iCHEF 補齊」可設定每個警示，前台會在候位列、桌位卡、訂單列與「流程警示」任務卡顯示超時狀態。舊 runtime 由 `20260512242000_add_workflow_warning_threshold_settings.sql` 補上預設關閉與分鐘數。

## 主要決策

- 前端全面 Vue-owned state，不新增 inline `onclick/onchange`、`data-action` 事件代理、`window.*` 全域 API 或 `innerHTML` 資料渲染。
- 先用 GitHub Pages 承載消費者線上點餐與 Web POS；硬體列印走 Capacitor Android APK 內的 `LanPrinter` TCP socket plugin，直接送 EZPL 到 GODEX DT2X。
- 後端沿用咖啡訂購專案經驗：Supabase PostgreSQL + Deno/Hono Edge Functions，金鑰放 GitHub Secrets 或 Supabase，不進 git。
